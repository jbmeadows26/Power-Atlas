# Eastern Axis — open-source intelligence analyst

The new **AI analyst** section is a country-filtered GitHub Pages interface backed by a daily GitHub Actions source-processing pipeline. It preserves the existing Neon API and Power Atlas root; GitHub Pages is the active hosting target. It requires no Raspberry Pi or AppDeploy.

## Five optional adapters
- **GPT Researcher** is provisioned as an on-demand, zero-API-key GitHub Actions research job: manually dispatch `Eastern Axis intelligence analyst` with `research=true` and `free_model=true` (default). The workflow starts a **temporary Ollama CPU container** with `qwen2.5:1.5b` and `nomic-embed-text`, uses GPT Researcher's **DuckDuckGo** retriever, and stores the report and its source list as unreviewed Actions artifacts for seven days. It never runs as a web backend, is not a paid model, and produces no authoritative report without human review. Small local models can produce poor or unsourced results: failed or unsourced research is **shown as error** rather than published. The existing credential-based research path remains optional when `free_model=false`, using `EA_OPENAI_API_KEY` and `EA_TAVILY_API_KEY` GitHub secrets.
- **OpenOSINT** automatically installs its pinned MCP implementation on the ephemeral Actions runner and performs a passive DNS check for the project's GitHub Pages hostname, `jbmeadows26.github.io`, at the daily source refresh. A repository variable `EA_OPENOSINT_DOMAIN` can override that scoped hostname. The connector also requests bounded, keyless GDELT geolocated-news leads; third-party GDELT claims are **never promoted to official-source intelligence**. No active scanning, email enumeration or private-person research is enabled.
- **Local Deep Research** needs an existing reachable and authenticated LDR server configured by `EA_LDR_URL` (variable), `EA_LDR_USERNAME` and `EA_LDR_PASSWORD` (secrets). Its private database, accounts, model and persistent host must be provisioned on authorized infrastructure. GitHub Pages and intermittent Actions runners are not durable substitutes.
- **OpenAleph** probes `GET /api/2/entities` at `EA_OPENALEPH_URL` (variable), with optional `EA_OPENALEPH_TOKEN` (secret). Its document index and Elasticsearch/PostgreSQL/Redis stack require a separately operated host; no entity matches publish automatically.
- **OpenCTI** probes `EA_OPENCTI_URL/graphql` (variable) with `EA_OPENCTI_TOKEN` (secret). The OpenCTI server and its stateful dependencies, users and integrations require persistent authorized infrastructure; API availability alone does not imply verified cyber intelligence imports.

**Current infrastructure limits:** This repository can publish static data and run short-lived jobs for free, but cannot host always-on OpenCTI/OpenAleph/LDR processes. Those three are deliberately **not configured** without a server and credentials; no paid or unapproved hosting is automatically created. See the [official OpenAleph deployment instructions](https://openaleph.org/docs/) and [OpenCTI Docker stack](https://github.com/OpenCTI-Platform/docker) for server provisioning.

## Free automated analysis (no API credentials)
The daily pipeline combines the existing official publication-change monitor, public **DOJ, FARA, and CISA intelligence intake**, and the source-linked **U.S., Five Eyes, NATO/EU, and Indo-Pacific allied assessments** already curated in the Defense intelligence API. Each record keeps its original publisher, title, URL, date, and explicit country tags. The analyst also publishes a separate directory of official allied source portals. Portals are discovery references and **do not count as ingested documents or verified evidence**. The source-health panel independently identifies unavailable allied assessment data rather than silently discarding that evidence family. DOJ/FARA/CISA imports remain **baseline metadata**, not confirmed misconduct or new alerts. Missing secondary intake is shown as unavailable rather than silently omitted.

An optional **Apache-2.0 MiniLM** sentence embedding model runs through [FastEmbed](https://github.com/qdrant/fastembed) on the temporary GitHub Actions CPU runner. It identifies possibly related **headlines across different publishers** and then requires compatible country and topic tags; similarity is **not** proof of independent corroboration. Topic labels and country counts also work without any model. The dashboard exposes the model's actual status: `available`, `unavailable`, `disabled`, or `insufficient-data`. Fallbacks never masquerade as AI analysis. None of this is a generative intelligence judgment or a forward-looking military threat score.

## Country inference without source tags
The daily processor runs an **auditable rule-based country/name recognition pass over the original publication title**. It recognizes unambiguous country names, demonyms, and a short list of places. Each matched record keeps `inferredCountries` alongside (never replacing) the official `countries` field, including ISO code, exact matched phrase, method (`title-country-name` or `title-place-name`), and a qualitative confidence label about textual recognition only.

- **Source tag:** The upstream collector explicitly supplied that country.
- **Title mention:** A publication title explicitly names a country or identifiable place; *not* proof that the incident happened there, that an actor is from there, or that a report confirms the claim.
- **Unassigned:** Neither evidence source identifies a country. Unassigned documents remain accessible as worldwide context.
- **Excluded from automatic association:** FARA registrant names and CISA product/vendor labels, publisher address/agency, domain names, ambiguous place names (such as "Georgia"), and single-letter ISO codes. A publisher in the United States does not mean a cyber vulnerability is a U.S. incident.
- **Review:** Any inferred country association must be checked against the original linked article before it supports an event assertion. Full-text extraction, NER models, entity resolution, and country-of-impact analysis are *not* claimed as deployed.

The Analyst keeps original and inferred counts separate. A selected country can display title-linked source evidence even if zero original-source tags exist. `quality.inferredOnlyCount` measures additional country-associated records, while `quality.countryTaggedCount` continues to count source tags only.

**Coverage boundary:** This is not a complete ingestion of every agency or historical document from every U.S. ally. Only the monitored feeds, scheduled official records and curated allied assessments are indexed. Untagged source material remains worldwide context; no source silence is interpreted as an all-clear.\n\n**Operational minimum:** original-source library, current change count, country coverage, subject breakdown, title search, baseline controls, publisher diversity, collection health and honest model status work without paid accounts. Full GPT Researcher/Local Deep Research report generation and OpenAleph/OpenCTI graph search still require their own authenticated servers/models. These are explicitly **not configured** until their live probes succeed.

## Publication and review
Only original-source titles, HTTPS source links, publishers, publication/detection dates, literal country mentions, auditable source-derived topic labels, and clearly limited semantic overlap are published. Invalid upstream schemas cause the workflow to fail closed rather than overwrite verified output. A new official report is not a new military deployment; mentioning a jurisdiction is not an accusation. LLM-generated documents are **unreviewed** and uploaded as seven-day GitHub Actions artifacts only for explicitly requested manual research. **Because this GitHub repository is public, treat artifact contents and workflow inputs as potentially public. Never include secrets, private intelligence, unpublished leads, or personal information.** Human verification of citations, original records, entity resolution, competing hypotheses and legal status is required before publishing any analytic assertions.

## Operation
Run the **Eastern Axis intelligence analyst** workflow with `research=false` for the first feed check; it then schedules at 06:17 UTC daily. Successful analyst workflow completion on `main` triggers the combined Pages release through `workflow_run` (including scheduled bot commits, which do not emit a follow-on push workflow). The Pages release rechecks Neon, mobile QA, and the root Power Atlas site before publishing `eastern-axis/public/analysis/manifest.json`. Keep provider secrets in GitHub Actions **Secrets**, never in repository variables or frontend bundles. The Pages interface shows each tool as disconnected until its live probe succeeds.
